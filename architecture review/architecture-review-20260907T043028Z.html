5. Split WorkflowTemplateLifecycleService's interface

After — two cohesive modules

addStage / addParticipant / setPermissions

Problem: the module isn't shallow (each method carries real logic — linked-list splice/detach, DRAFT guards, participant validation) but its interface is wide: 12 public methods spanning two distinct concerns.

Solution: split by concern — template/version authoring vs. stage/participant editing — into two deep modules instead of one wide one.

  • Leverage: each interface maps to one concern, easier to learn
  • Locality: a stage-editing bug no longer risks touching template-version code

6. Fold the repeated admin gate into one helper

Speculative in-process

core/orchestrator/ClientRoleCatalogueOrchestrationService.java · RankCatalogueOrchestrationService.java · CompanyRoleAccessChangeOrchestrationService.java:82-102

flowchart LR
  M1["listRoles"] -.->|same 2 lines| G["resolve + requirePlatformAdmin"]
  M2["listPermissions"] -.->|same 2 lines| G
  M3["updateRoleDefaultPermissions"] -.->|same 2 lines| G
  M4["toggleRole"] -.->|same 2 lines| G

Problem: ClientRoleCatalogueOrchestrationService and RankCatalogueOrchestrationService each repeat an identical resolve + requirePlatformAdmin pair across 3–4 methods — coincidental duplication of a small idiom, not shared business complexity.

Solution: a private requirePlatformAdmin(Long actingIdentityAccountId) helper, same pattern several other orchestrators already use for their own gates.

Separately noted: CompanyRoleAccessChangeOrchestrationService.getGrants holds the densest inline branching of any orchestrator method reviewed (BPL-staff check → own-profile lookup → companyAdmin flag → uuid equality). CLAUDE.md tolerates authorization logic in orchestrators, so this is a softer smell than the other candidates — worth a look, not a rewrite.

Naming note: this method still reads ownProfile.get().companyAdmin(), a boolean-flag field name from before the Client Role Model Redesign, which now represents Client Admin as a real UserRoleAssignment against the CLIENT_ADMIN Client Role (see CONTEXT.md). Not a depth problem — a naming-migration residue worth tracking alongside the rest of the Company→Client rename (`orderEngine-wls`).

Candidate 1 — collapse the registration-triage gate into AccessGuard
