# v2: one continuous 3D map at /v2/, beside the original site

v2 re-presents the same material as a place you travel through rather than pages you turn. It lives at `/v2/` as a second Vite entry (`v2/index.html` → `src/v2/main.ts`); the original site at `/` is untouched. GitHub Pages deep links work the same way as ADR-0002: `public/404.html` now keeps two path segments when the second is `v2`, so `/v2/intro/agents` round-trips through `/v2/?/intro/agents`. Routes use step slugs (`/v2/intro/agents`); numeric v1-style paths (`/v2/intro/10`) still resolve and are rewritten.

**Three.js is the one new dependency.** It is loaded lazily (its own chunk, after the reading panel has painted) so text never waits on WebGL. Everything else stays framework-free, consistent with the repo's stance.

**Engine and overlay never call each other.** `src/v2/core/state.ts` holds a small observable store (route, sandbox params, quality, sound, layout inset) and an event emitter (replay beats, dial ticks, arrival, hotspot positions). The engine (`src/v2/engine/`) reads the store and draws; the DOM overlay (`src/v2/ui/`) reads the store and renders text. `main.ts` is the only file that knows both exist. Each 3D metaphor is a *rig* (`src/v2/scenes/`) implementing `update(ctx)` / `dispose()` and never touching the DOM — deep-dive hotspots are anchors the engine projects to screen space, rendered as real buttons so they stay focusable and readable by screen readers.

**Metaphors, not flowcharts.** Nine rigs cover every station: a boids colony (hand-offs, guardrails, review, design options), a loom (token sampling, reasoning tokens), a water pool (context and statelessness), a jellyfish-like agent (loops, sub-agents, model tiers), lock tumblers and key/socket (hooks, TDD, MCP, effort dials), folding paper (skills, plugins, prompts, specs, handoff), sediment strata (memory, ADRs), mycelium (graphs, wayfinder maps, module trees, legacy code) and a Calder mobile (model selection). Each step's knobs (temperature, context fill, loop steps, effort) feed the rig every frame.

**Visual language carries v1's brief forward** (docs/design-brief.md): warm paper, ink, orange/green as functional signals only, no gradients or glass. The ground is a topographic sheet whose contours rise around each section; distance fog fades to paper, not black.

**Navigation is an orbital dial**, not a sidebar: every station is a tick on one ring, with momentum, magnetic snapping, proximity-stretching ticks, wheel/trackpad velocity, keyboard and touch. On phones it becomes a half-hidden edge wheel above a bottom-sheet reader. The hub opens a plain index of all stations as the accessible fallback.

**Performance & fallbacks.** Rigs are built only near the camera and disposed beyond a radius; distant rigs update at a third of the rate with fewer particles (LOD); three.js frustum culling handles the rest. An offscreen render target with a moving-average frame-time controller scales resolution between 0.5× and 1× (`quality: auto`), with fixed `high`/`low` overrides. Rendering pauses in hidden tabs. No WebGL, or a lost context, switches to a static mode with the full text, replays and screenshots. `prefers-reduced-motion` replaces flights with a short paper fade and shows replays whole.

**Examples are replays of real screenshots.** Every screenshot in `backendExample/` and `frontendExample/` (77) is used by some step — a dev-time audit (`src/v2/content/audit.ts`) warns if one isn't, or if a `[[term]]` has no glossary entry. Replay lines quote the screenshots verbatim; where v1 captions had drifted from what a frame shows, v2 follows the frame.

Considered and rejected: rebuilding v1 in place (it is the stable, text-first artifact the brief says must outlive the session); a router/framework for v2 (the store + History API covers it in ~70 lines); post-processing via three's EffectComposer (one custom paper pass does resolution scaling and grain in a single draw).
